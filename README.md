# 세일즈노트 (SalesNote) MVP

영업사원은 휴대폰 웹 앱으로 **명함 촬영 → 고객카드 → 일정 → 미팅 녹음 → AI 회의록**을 남기고,
팀장은 관리 웹에서 **대시보드·팀 일정·활동 타임라인·미팅 카드·고객사**를 보는 영업관리시스템의 첫 버전입니다.

- 파일럿: 비즈메시징 사업팀 (약 15명), 2026년 12월 ~ 2027년 1월 시작
- 기준 문서: 「세일즈노트 영업관리시스템 기획서」, 「세일즈노트 MVP 클릭 시안」
- 앱과 웹은 **하나의 코드**입니다. `/m` 아래가 영업사원 앱(PWA), `/admin` 아래가 팀장 웹입니다.

> 명함 OCR, 음성인식(STT), AI 요약은 아직 API 키가 없어 **가짜 응답(mock)** 으로 동작합니다.
> 실제 API 연결 방법은 아래 「AI 기능 실제 연결」을 보세요.

## 1. 설치하고 실행하기

필요한 것: **Node.js 20 이상** (권장 22), npm

```bash
git clone https://github.com/biofa1620/salesnote.git
cd salesnote
cp .env.example .env      # 설정 파일 만들기 (Windows: copy .env.example .env)
npm install               # 패키지 설치
npm run setup             # DB 만들기 + 샘플 데이터 넣기
npm run dev               # 개발 서버 실행 → http://localhost:3000
```

처음 화면에서 사용자를 고르면 들어갑니다.

| 계정 | 들어가는 곳 |
|---|---|
| 오팀장 (팀장) | 팀장 관리 웹 `/admin` |
| 김다우 외 4명 (영업사원) | 영업사원 앱 `/m` (휴대폰 화면 크기로 보면 앱처럼 보입니다) |

자주 쓰는 명령:

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 (코드 고치면 바로 반영) |
| `npm run build && npm start` | 운영용 빌드 후 실행 |
| `npm run db:reset` | DB를 지우고 샘플 데이터로 다시 채우기 |
| `npm run cleanup:audio` | 보관 기간(기본 90일)이 지난 녹음 원본 삭제 |

### 외부 서버에 올려 시험하기

고정 주소로 휴대폰 앱과 팀장 웹을 시험하려면 **[배포하기.md](배포하기.md)** (Railway 기준)를 보세요.
`Dockerfile` 이 들어 있어 다른 서비스나 사내 서버에도 올릴 수 있습니다.
외부에 올릴 때는 `.env` 의 `ACCESS_CODE` 를 꼭 정하세요. 코드를 입력한 브라우저만 들어올 수 있습니다.

### 휴대폰에서 시험하기 (맥 + 터널)

- 같은 와이파이에서 `http://<PC의 IP>:3000/login` 으로 열면 화면은 볼 수 있습니다.
- **카메라·마이크는 HTTPS에서만** 동작합니다. 휴대폰으로 녹음까지 시험하려면 HTTPS 주소가 필요합니다.
  (예: 사내 서버에 인증서를 붙여 배포하거나, `ngrok http 3000` 같은 터널 사용)
- HTTPS가 아니면 녹음은 "녹음 없이 진행" 모드로 흐름만 시험됩니다.
- 휴대폰 브라우저 메뉴의 **홈 화면에 추가**를 누르면 앱처럼 설치됩니다(PWA).

## 2. 기능 범위 (MVP)

### 영업사원 앱 `/m`

| 화면 | 경로 | 기능 |
|---|---|---|
| 홈 | `/m` | 오늘 일정, 녹음 시작 버튼, 해야 할 일(회의록 확정 필요·기한 임박·14일 이상 연락 없는 고객) |
| 명함 촬영 | `/m/scan` | 촬영/사진 선택 → OCR로 자동 입력 → 확인 후 저장. 이미 등록된 회사면 안내 |
| 고객 | `/m/customers` | 팀 전체 명함 목록·검색 (명함은 회사 소유) |
| 고객카드 | `/m/customers/[id]` | 전화·메일·일정·녹음 바로가기, 딜 단계 변경, 통화 기록 메모, 타임라인 |
| 일정 | `/m/schedule` | 월간 미니 달력, 날짜 누르면 그날 일정, 주간으로 접기, 회의록에서 찾은 일정 |
| 일정 추가 | `/m/schedule/new` | 고객 미팅/내부/할 일, 팀장 동행 요청 |
| 미팅 녹음 | `/m/record` | 녹음·일시정지·종료 → 음성인식 → AI 요약 → 미팅 카드 생성 |
| 회의록 | `/m/meetings`, `/m/meetings/[id]` | AI 요약 카드 확인·수정·확정, 다음 할 일을 일정에 추가, 녹취록, 팀장 코멘트 |

### 팀장 웹 `/admin`

| 화면 | 경로 | 기능 |
|---|---|---|
| 대시보드 | `/admin` | 이번 주 미팅·신규 명함·회의록 확정률·관리 필요 고객, 팀원별 활동, 살펴볼 고객, 최근 미팅 카드 |
| 팀 일정 | `/admin/schedule` | 팀원×요일 주간 표(회의록 없음·동행 요청 표시), 동행 요청 수락/거절, 계획 대비 실적 |
| 활동 타임라인 | `/admin/timeline` | 팀원·유형(미팅/통화/명함/일정)별 활동 기록 |
| 미팅 카드 | `/admin/meetings` | 확인 필요/확정/회의록 없음 필터, 요약 상세, 코칭 코멘트 |
| 고객사 | `/admin/customers` | 고객사 목록(최근 접촉, 14일 이상 미접촉 경고), 딜 단계, 담당자 명함, 최근 활동, 다음 일정 |

### 추가 기능 (MVP 2차)

| # | 기능 | 위치 | 비고 |
|---|---|---|---|
| 1 | 기업 신용·재무·공시·뉴스 연동 | 앱 고객카드, 웹 고객사 | 새 고객사는 명함 저장 때 자동 연동(회사명이 정확히 한 곳과 일치할 때), 아니면 후보 중 선택. **지금은 샘플 데이터** — `src/lib/company-info/real.ts` 에 DART·뉴스·KED/NICE API 연결 |
| 2 | 통화 후 메모 팝업 | 앱 고객카드 '전화' 버튼 | 앱에서 건 통화를 마치고 돌아오면 10초 음성 메모/한 줄 메모 팝업. 웹 앱은 일반 수신 전화를 감지할 수 없음 (네이티브 앱 단계에서 확장) |
| 3 | 딜 정체·누수 경보 | 웹 `/admin/pipeline`, 대시보드, 앱 홈·고객카드 | 같은 단계 10일 이상(`STALL_DAYS`) 또는 후속 일정 없음 → 빨간 경고 |
| 4 | 선행지표 비교 | 웹 `/admin/indicators` | 명함·미팅·통화·자료 전송·회의록 확정률·후속 조치 속도. 견적 발송량·회신 속도는 2단계 |
| 5 | 자료 즉시 전송 | 웹 `/admin/materials`(등록), 앱 `/m/materials`(전송) | 휴대폰 '공유하기'로 카카오톡·문자에 링크 전송, 고객 열람 기록. 고객 링크 `/s/<토큰>` 은 로그인 없이 열림 |

### 견적 (MVP 3차)

| 단계 | 어디서 | 내용 |
|---|---|---|
| 작성 | 앱 고객카드 → **견적 작성** (`/m/quotes/new`) | 상품 고르기 → 수량·단가 입력. 정가 그대로면 바로 발송 가능, **정가와 다른 단가가 하나라도 있으면 팀장 승인 요청** |
| 승인 | 팀장 웹 **견적** (`/admin/quotes`) | 품목별 정가 대비 차이를 보고 승인/반려(사유). 상품·정가도 여기서 관리 |
| 발송 | 앱 견적 화면 → **견적서 보내기** | 휴대폰 공유하기로 카카오톡·문자·메일에 견적서 링크 전송. 딜이 제안 전 단계면 '제안'으로 올라감 |
| 고객 | 견적서 링크 `/q/<토큰>` | 로그인 없이 열림, 인쇄·PDF 저장. 열람 횟수가 기록되고 활동 타임라인에 남음 |
| 수정 | 반려·발송 뒤 **수정 견적 만들기** | 2차, 3차 버전으로 새로 작성 |

견적서의 공급자 이름은 `.env` 의 `SELLER_NAME` 으로 바꿀 수 있습니다. 상품 정가의 처음 값은 샘플입니다.

### MVP에서 뺀 것 (기획서 로드맵 2단계 이후)

메일·캘린더·그룹웨어·ERP 연동, 알림톡·문자 발송, 신호 기반 수주확률, 녹음 동의 화면, 사내 계정 로그인(SSO).

## 3. 폴더 구조

```
src/
  app/
    login/            로그인 (MVP용 사용자 선택)
    m/                영업사원 앱 화면
    admin/            팀장 웹 화면
    api/              파일 업로드가 필요한 API (OCR, 명함 저장, 녹음 업로드, 파일 보기)
    actions.ts        입력 폼이 부르는 서버 함수 (일정 추가, 통화 기록, 회의록 확정, 코멘트 …)
  components/         공통 화면 부품 (하단 메뉴, 월간 달력, 녹음기 …)
  db/
    schema.ts         데이터 모델 (테이블 정의)
    index.ts          DB 연결
    seed.ts           샘플 데이터
  lib/
    ai/               AI 기능 (mock.ts = 가짜 응답, real.ts = 실제 API 자리)
    session.ts        로그인 사용자 확인
    storage.ts        파일 저장소 (명함 사진, 녹음)
    queries.ts        공통 조회 (고객사별 마지막 접촉일)
    format.ts         날짜 표시, 딜 단계
scripts/cleanup-audio.ts  녹음 원본 자동 삭제
public/                   PWA 설정(manifest), 서비스 워커, 아이콘
```

### 기술 구성

| 영역 | 사용 기술 | 비고 |
|---|---|---|
| 화면·서버 | Next.js 15 (App Router), React 19, TypeScript | 앱과 웹이 한 프로젝트 |
| DB | SQLite + Drizzle ORM | 운영은 PostgreSQL 권장 (아래 참고) |
| 파일 | 로컬 폴더 `uploads/` | 운영은 S3 등 객체 저장소 권장 |
| 스타일 | CSS 한 파일 (`src/app/globals.css`) | 색·간격은 클릭 시안과 동일 |

## 4. 데이터 모델

DB는 하나이고, 테이블을 나누어 ID로 연결합니다. 모든 기록은 **고객사** 아래로 모입니다.

| 테이블 | 내용 | 연결 |
|---|---|---|
| `users` | 사용자 (REP 영업사원 / LEAD 팀장 / ADMIN) | |
| `companies` | 고객사 | |
| `contacts` | 담당자(명함). 등록자가 아니라 회사 소유 | 고객사 |
| `deals` | 딜(영업기회): 발굴·미팅·제안·협상·수주·실주 | 고객사, 담당 영업 |
| `events` | 일정: 고객 미팅/내부/할 일, 동행 요청 | 고객사, 담당자, 딜 |
| `meetings` | 미팅 + 녹취록 + AI 요약 카드 + 녹음 파일 경로 | 일정, 고객사 |
| `comments` | 팀장 코칭 코멘트 | 미팅 |
| `activities` | 활동 기록(명함·통화·일정·미팅·자료) → 활동 타임라인 | 사용자, 고객사 |
| `materials` | 자료실 파일 (브로슈어·규격서) | |
| `shares` | 자료 전송 링크와 고객 열람 횟수 | 자료, 담당자, 고객사 |
| `products` | 상품·정가 (부가세 별도) | |
| `quotes`, `quote_items` | 견적서와 품목 (승인 상태, 발송·열람 기록, 버전) | 고객사, 담당자, 딜 |

`companies.info` 에 기업 정보(재무·신용·공시·뉴스), `deals.stage_changed_at` 에 단계가 바뀐 날짜(정체 경보 기준)가 저장됩니다.

스키마를 고친 뒤에는 `npm run db:push` 로 DB에 반영합니다.

## 5. AI 기능 실제 연결

화면과 API는 `src/lib/ai/types.ts` 의 인터페이스만 사용합니다.

```ts
readBusinessCard(image, mimeType) → { name, company, department, title, phone, email }
transcribe(audio, mimeType)       → [{ speaker, text }, …]
summarize({ companyName, transcript }) → { points, products, budget, decisionMaker, competitor, concern, nextActions }
```

1. `src/lib/ai/real.ts` 의 세 함수를 실제 API 호출로 채웁니다.
   - 명함 OCR 후보: 네이버 클로바 OCR(명함 특화), Google Cloud Vision
   - 음성인식 후보: 네이버 클로바 스피치, 리턴제로, Whisper (한국어·화자 분리 성능 비교)
   - 요약 후보: Claude 등 LLM API (데이터 학습 미사용 조건 확인, 응답을 JSON 형식으로 받도록 지시)
2. `.env` 에 키를 넣고 `AI_PROVIDER="real"` 로 바꿉니다.
3. 개인정보 처리방침에 외부 API 위탁 사실을 적습니다.

## 6. 운영 배포 전 할 일 (개발팀 인계 체크리스트)

- [ ] **로그인 교체**: `src/lib/session.ts` 와 `/login` 은 시범용입니다. 사내 계정(SSO 등)으로 바꿔야 합니다.
- [ ] **DB 이전**: SQLite → PostgreSQL. `src/db/schema.ts` 를 `drizzle-orm/pg-core` 로 옮기고 `drizzle.config.ts` 의 dialect를 바꿉니다.
- [ ] **파일 저장소**: `src/lib/storage.ts` 를 S3 등으로 교체 (명함 사진·녹음 파일).
- [ ] **녹음 원본 삭제 예약**: 하루 한 번 `npm run cleanup:audio` 실행 (예: cron `0 3 * * *`). 기간은 `.env` 의 `AUDIO_RETENTION_DAYS`(기본 90일 = 3개월).
- [ ] **HTTPS**: 카메라·마이크 사용에 필수.
- [ ] **서버 시간대**: `.env` 의 `TZ="Asia/Seoul"` 유지 (날짜·시간 표시 기준).
- [ ] **권한 점검**: 영업사원은 본인 회의록만 수정, 팀장 웹은 LEAD/ADMIN만 접근 (현재 구현됨). 녹취 원본 열람 로그는 2단계.
- [ ] **AI 실제 연결**: 위 5절.
- [ ] **기업 정보 실제 연결**: `src/lib/company-info/real.ts` 구현 + `.env` 의 `COMPANY_INFO_PROVIDER="real"`. 신용등급은 KED·NICE 유료 계약 필요.
- [ ] **자료 링크 보안**: 고객 링크는 로그인 없이 열립니다. 필요하면 만료 기간을 추가하세요 (`shares` 테이블).

## 7. 알려진 제약

- 샘플 데이터의 회사·사람 이름은 모두 지어낸 예시입니다.
- 웹 앱(PWA)은 일반 전화의 수신·발신을 감지할 수 없습니다. 통화 기록은 고객카드에서 직접 남깁니다.
- 아이폰은 '홈 화면에 추가' 후에도 백그라운드 녹음이 제한될 수 있으니, 녹음 중에는 화면을 켜 두는 것을 안내해야 합니다.
